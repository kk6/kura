# ADR-0021: 特徴量を `features.db` に分け、計算し直せるものとして扱う

## Status

accepted

## Date

2026-11-14

## Context (Why)

類似画像検索の特徴量は、2万枚で100MB 前後になる見込みだった（スパイクでは約127MB）。ライブラリの DB（`kura.db`）は、バックアップ（NFR-07）と移行前の写し（[ADR-0027](0027-backup-before-migration.md)）の対象になる。外付けドライブは一時的に外れることがある。

## Intent (What)

- 特徴量は `kura.db` に入れず、`.kura/features.db` に置く（2026-11-14、利用者と決めた）。書くのは Rust だけにする
- 特徴量は画像から計算し直せるので、バックアップに含めない
- 特徴量のキーは、画像の SHA-256、観点、モデル名にする。古い `kura.db` をバックアップから戻しても、同じ場所で中身が変わっても、別の画像の特徴量に結び付かない
- `features.db` が無い、SQLite のファイルでない、壊れている、版がアプリの知っている版と違う、のどれかなら、消して空で作り直す（2026-11-15、利用者と決めた）
- ディスクの I/O エラー、ロック、権限のエラーでは消さない。計算を止めてエラーを出し、次のきっかけで開き直す（2026-11-15、利用者と決めた）
- 計算の進め方（計算できなかった画像、再計算）は、2026-11-15 に利用者と決めた。作り方は `docs/tasks/phase3-design.md` にある

## Constraints

- 外付けドライブが一瞬外れただけで、計算済みの特徴量を失わない

## Alternatives Considered

- **特徴量を `kura.db` に入れる**：バックアップと移行前の写しが、その分だけ重くなるので却下した
- **キーを画像の id にする**：古い `kura.db` を戻したときや、中身が変わったときに、別の画像の特徴量に結び付くおそれがあるので、SHA-256 にした
- **I/O エラーでも作り直す**：外付けドライブが一瞬外れただけで、計算済みの特徴量を失うので却下した

## Consequences

- `kura.db` のバックアップから戻した後は、特徴量の一部を計算し直すことがある
- 全部を計算し直したいときは、アプリを終了して `.kura/features.db` を消す
