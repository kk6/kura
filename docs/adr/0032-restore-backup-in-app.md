# ADR-0032: 書き出した管理情報を、アプリの中で戻せるようにする

## Status

accepted — supersedes [ADR-0031](0031-backup-export-only.md)

## Date

2026-11-20

## Context (Why)

管理情報を戻すには、利用者がアプリを終了して `kura.db` を手で置き換える必要がある。`kura.db-wal` と `kura.db-shm` を消し忘れると、DB が壊れるおそれがある。FR-107 で、この手順をアプリの中の操作にする。

## Intent (What)

- 戻す前に、今の管理情報の写しを `.kura/backups/kura-before-restore-<日時>.db` に残す。写しを書けなければ戻さない。写しは自動で消さない
- 選んだ管理情報に記録された画像のうち、ライブラリの中に見つかるものが半分に満たなければ警告する。利用者が続けると選んだときだけ戻す
- アプリより新しい版の管理情報は戻さない。古い版の管理情報は、戻した後に移行する
- 取り込みと差分検出の途中では戻さない。ボードの編集を保存し終えてから戻す。保存に失敗したら戻さない
- 特徴量は消さない

## Non-goals

- 画像ファイルとサムネイルを戻すこと

## Alternatives Considered

- **確かめずに戻す**：別のライブラリの管理情報だと、ほぼすべての画像が「見つからない」になる。写しから戻し直せるが、利用者が気づくのが遅れるので却下した
- **DB にライブラリの ID を足す**：今までに書き出した管理情報には ID がなく、確かめられないので却下した

## Consequences

- 戻すたびに、`.kura/backups/` に写しが1つ増える
- 判定は見つかる画像の数で行うので、画像の大半を入れ替えた同じライブラリでも警告が出る
- 移行前の写しと戻す前の写しが、同じ場所に並ぶ
