# ADR-0005: ファイルを動かす操作は、予定を記録してから3段階で行う

## Status

accepted

## Date

2026-11-04

## Context (Why)

カテゴリはフォルダに対応するので、カテゴリの設定、名前変更、ゴミ箱への移動などで実ファイルを動かす。途中でアプリが落ちたり電源が切れたりしても、画像を失わず、DB とファイルの食い違いを検出できる必要がある（NFR-06）。ライブラリは外付けドライブ（APFS、HFS+、exFAT）にも置ける（NFR-13）。フェーズ1の前のスパイク（`spikes/crash-safe-move/`）で確かめた。

## Intent (What)

- ファイルを動かす操作（移動、名前変更、カテゴリのフォルダの移動・名前変更、ゴミ箱への移動と復元）は、次の3段階で行う
  1. 移動の予定を DB に記録してコミットする
  2. 移動先を上書きしない方法でファイルを移す
  3. 画像の情報の更新と予定の削除を、1つのトランザクションでコミットする
- 起動時に予定が残っていれば、実ファイルの位置に合わせて完了させるか取り消す。どちらとも決められなければ、予定を残して利用者に知らせる
- どの段階で処理が止まっても、画像は失われず、食い違いを検出して元に戻せる
- 予定の移動元と移動先は、ライブラリのルートからの相対パスで記録する。外付けドライブのマウント先が変わっても後始末できる

## Constraints

- 上書きしない（名前の衝突は「名前の衝突」の節のとおり）
- 大文字・小文字だけの名前変更もできる

## Alternatives Considered

- **予定を記録せずに、移動と DB の更新だけを行う**：途中で止まると、画像の場所と DB が食い違ったまま残る。スパイクで3段階の手順と比べ、3段階を採った
- **予定に絶対パスを記録する**：外付けドライブのマウント先が変わると、後始末できなくなるので却下した
- **exFAT でも上書きしない名前変更（`renamex_np` の `RENAME_EXCL`）を使う**：exFAT ではこの指定が使えない（`ENOTSUP`。フェーズ1のタスク2でディスクイメージを作って確かめた）。exFAT では、移動先がないことを確かめてから通常の rename を行う。HFS+ と大文字・小文字を区別する APFS では使える
- **exFAT で大文字・小文字だけの名前変更を直接行う**：exFAT は存在の確認で大文字・小文字を区別しない。そこで、移動先のフォルダの一時的な名前（`.kura-tmp-<予定のid>`）を経由する。後始末で一時的な名前が残っていれば、移動元に戻す（コピーなら消す）

## Consequences

- 途中で落ちても画像を失わない。手順は TLA+ のモデル（`.claude/skills/verify-crash-safe-move/`）でも確かめている
- exFAT では、存在を確かめてから rename するまでの間に Finder で同名のファイルが置かれると、上書きされうる
- ファイルを動かす操作はすべて、この手順を通す必要がある
