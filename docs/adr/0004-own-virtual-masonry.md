# ADR-0004: 一覧の仮想スクロールを自前で作る

## Status

accepted

## Date

2026-11-04

## Context (Why)

一覧は、縦横比を保つメイソンリー型でサムネイルを並べる（FR-501）。2万枚のライブラリでも、スクロールが引っかからずに動く必要がある（NFR-01）。画面は WKWebView で動く。フェーズ1の前のスパイク（`spikes/masonry-scroll/`）で確かめた。

## Intent (What)

- 2万枚・12列のメイソンリーを、WKWebView で 60fps を保ってスクロールできる
- 全体の配置は、DB に保存した画像の幅と高さから先に計算する。画面に描くのは、表示している範囲と、その上下1画面分だけにする
- サムネイルは、ライブラリの `.kura/` の下のファイルを画面が直接読む。画面が読める範囲は、開いたライブラリの画像と `.kura/thumbs/` の下だけにする。DB とゴミ箱は読めない

## Constraints

- NFR-01：2万枚でスクロールが引っかからない

## Alternatives Considered

- **仮想スクロールのライブラリを使う**：スパイクでは比べていない。自前の作りが 2万枚・12列で 60fps を保てたので、ライブラリを足さずにそれを採った
- **サムネイルの読める範囲を `.kura/` の下だけにする**（スパイクの作り）：拡大表示（FR-508）で元の画像を読むために、開いたライブラリの画像まで広げた

## Consequences

- 配置の計算と表示範囲の計算を、自分で保守する
- 計測の結果は `spikes/masonry-scroll/README.md` にある
