# ADR-0033: 元が同じ画像を1枚にまとめるとき、ボードの配置を置き換え、タグと元URLを引き継ぐ

## Status

accepted

## Date

2026-11-23

## Context (Why)

ライブラリには、同じ写真から大きさ、トリミング、色味を変えた画像（元が同じ画像）がたまる。中身が違うので、重複（SHA-256）の検出では見つからない。FR-610 と FR-611 で、元が同じ画像から1枚を残し、ほかをゴミ箱へ移せるようにする。

ゴミ箱へ移す画像には、タグや元URLが付いていたり、ボードに置かれていたりする。そのまま移すと、ボードには状態の枠が出て、付けたタグと元URLは残す画像に残らない。整理したつもりで、利用者の分類と作画の配置が失われる。

基準に使う類似度にも決めることがある。類似画像検索の結果の並びに使う値は、観点ごとに基準画像に対して平均0・標準偏差1にそろえている（ADR-0022）。この値は基準画像ごとに意味が変わるので、どの画像にも同じしきい値を当てられない。

## Intent (What)

- 「元が同じ」とみなすかは、内容の観点の、そろえる前の類似度とライブラリ全体で同じしきい値で決める。構図とポーズは使わない。左右反転は含めない
- 1枚にまとめると、残さない画像のボードの配置は残す画像に置き換わる。位置、表示の幅、回転、反転、グレースケールは保ち、縦横比が違えば高さが合い、トリミングは外れる。ボードを開いていなくても置き換わり、ボードの取り消しの履歴には入らない
- 残す画像には、選んだ全部の画像のタグを合わせたもの（利用者が外したものを除く）が付く。残す画像に元URLがなければ、ほかの画像の元URLが付く。メモは引き継がない
- 残さない画像はゴミ箱へ移り、ゴミ箱から戻せる
- ゴミ箱から戻しても、残した画像に足したタグと元URL、置き換えたボードの配置は元に戻らない

## Non-goals

- まとめた操作を記録して、あとで全体を取り消すこと。利用者が戻し忘れや戻し違いで困る例が出たら考え直す
- メモの引き継ぎ
- 左右反転した写しを元が同じとみなすこと

## Constraints

- 画像ファイルは消さない。残さない画像はゴミ箱へ移すだけにし、完全削除は利用者がゴミ箱を空にしたときだけ
- ファイルを動かす手順は、途中で落ちても画像を失わない今の手順に乗せる（NFR-06）

## Alternatives Considered

- **ボードの配置を置き換えない（状態の枠のまま）**：1枚にまとめるたびに、作画用に組んだボードに穴が空く。利用者が置き直す手間が増えるので却下した
- **縦横比が合うときだけ置き換える**：トリミング違いの組では縦横比がほとんど合わず、置き換わる場面が少ない。置き換わるかどうかが利用者から見て予想しにくいので却下した
- **操作を記録し、ゴミ箱から戻したときにタグ、元URL、配置も元に戻す**：記録を持つ所と、戻すまでの間に利用者が加えた変更とぶつかったときの決まりが要る。ゴミ箱から戻す操作が今より複雑になる。得られるものに比べて手間が大きいので却下した
- **そろえた類似度（ADR-0022 の値）でしきい値を決める**：基準画像ごとに値の意味が変わり、ライブラリ全体から組を探す FR-611 で同じ基準を当てられないので却下した

## Consequences

- ボードの配置と、付けたタグ・元URLを失わずに整理できる
- 縦横比の違う画像に置き換わると、ボード上の見え方（高さ、トリミング）が変わる。直すには利用者が配置を調整する
- ゴミ箱から戻すと、残した画像とゴミ箱から戻した画像の両方に同じタグが付いた状態になる。ボードは残した画像を指したまま
- 構図を使わないので、内容は同じでも構図がまったく違う別の写真（同じ場所で撮った別の写真など）を、元が同じとみなすことがある。しきい値の実測（フェーズ4b のタスク13）で確かめる
