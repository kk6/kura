# ADR-0028: 設定を、アプリ全体の設定とライブラリの DB の2か所に分ける

## Status

accepted

## Date

2026-11-05

## Context (Why)

設定には、どのライブラリでも同じ値を使いたいもの（サムネイルの大きさなど）と、ライブラリの中身に結び付くもの（閉じたカテゴリなど）がある。外付けドライブが外れていても、「最近使ったライブラリ」の一覧は出したい。開発版とリリース版は、アプリの ID が同じである。

## Intent (What)

- アプリ全体の設定は、アプリのデータフォルダの `settings.json` に置く。どのライブラリを開いても同じ値を使う（2026-11-05、フェーズ1のタスク18で利用者と決めた）
- ライブラリの中身に結び付く状態は、ライブラリの DB に置く。ライブラリを移しても、DB のバックアップから戻しても残る
- 「最近使ったライブラリ」の一覧は、ライブラリの中に置かず、アプリのデータフォルダに置く
- 開発版（`npm run tauri dev` とデバッグビルド）は、アプリのデータフォルダの下の `debug/` に一覧と設定を置く（2026-11-09 に足した）

## Alternatives Considered

- **画面側の `localStorage` に置く**：使わない。以前 `localStorage` に置いていた値は引き継がない（フェーズ1の完了の確認より前で、本物の資料ではまだ使っていなかったため）
- **「最近使ったライブラリ」をライブラリの中に置く**：外付けドライブが外れていると一覧を出せないので却下した
- **開発版もリリース版と同じ場所を使う**：開発版がリリース版の一覧から本物のライブラリを自動で開き、DB を新しい版に移行してしまうので却下した

## Consequences

- 設定を足すたびに、どちらに置くかを決める必要がある
- 開発版で本物のライブラリを手で選んで開くと、移行は起こる。そのときは移行の前に `kura.db` の写しが残る（[ADR-0027](0027-backup-before-migration.md)）
