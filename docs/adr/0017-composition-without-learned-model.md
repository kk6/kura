# ADR-0017: 構図の観点は、学習済みモデルを使わない特徴量で作る

## Status

accepted

## Date

2026-11-15

## Context (Why)

類似画像検索の「構図」の観点では、人物が画面の右寄りにいる、あおりのアングル、のような画像の大まかな形と配置を比べたい（5.6）。フェーズ3の前半（3a）の最初のスパイク（`spikes/similarity/`）で、単純な特徴量で足りるかを目で見て確かめた。

## Intent (What)

- 構図は、縮めたグレースケール画像（16×16）と、格子ごとのエッジの向きの分布（4×4の格子、8方向）で作る。類似度は2つの平均にする。学習済みモデルは使わない
- 3a をこの方法で進める（2026-11-15、スパイクの並びを見て利用者と決めた）
- 3b でも見直さない（2026-11-18、タスク12で利用者が決めた）。ポーズを足した後に利用者が自分のライブラリで使い、足りなければフェーズ4で見直す
- 左右反転した画像を、同じ構図とみなさない

## Alternatives Considered

- **被写体の位置を使う方法**：3b の開始時に見直すかを決めることにしていた。2026-11-18 に、3b では見直さないと決めた
- **左右反転した画像を同じ構図とみなす**：入れない。ポーズは反転を同じとみなす（[ADR-0019](0019-rtmpose-m-for-pose.md)）

## Consequences

- 構図の計算は1枚 0.2ms 未満で、内容の計算に比べて無視できる
- グレースケールは明暗の配置に強く反応する（暗い背景の人物を基準にすると、暗い画像が並ぶ）
- 画面のスライダーの名前は「明暗と線の配置」にした（[ADR-0022](0022-normalize-similarity-per-aspect.md)）
