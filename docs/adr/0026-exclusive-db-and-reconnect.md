# ADR-0026: ライブラリの DB を排他モードで開き、ディスクの I/O エラーでは開き直す

## Status

accepted

## Date

2026-11-13

## Context (Why)

フェーズ2のタスク18の確認で、外付けドライブを外したあとの保存で、アプリが落ちた。ライブラリは外付けドライブにも置ける（NFR-13）。ボードは自動保存し、保存に失敗している間は、切り替えと通常の終了を中止する（5.7）。

## Intent (What)

- DB は排他モードで開く。Kura が開いている間は、ほかのプロセス（別の Kura、`sqlite3` など）がライブラリの DB を開けない。後から開いた Kura には「ほかの Kura が開いています」と出す（2026-11-13、利用者が決めた）
- 外付けドライブが外れても、保存がエラーになるだけで、アプリは落ちない
- DB の操作がディスクの I/O エラーで失敗したら、次の操作の前に古い接続を閉じて、同じライブラリの DB を開き直す。つなぎ直した外付けドライブで、ボードの「再試行」やギャラリーの操作を続けられる（2026-11-13、利用者が決めた）
- 開き直しても、ボードの編集の状態は残す。外れていた間の編集を保存できる。DB の revision が進んでいれば、上書きせずに断る
- このときの画面のエラーは「ライブラリのドライブを読めません。ドライブをつなぎ直してから、もう一度試してください」とし、SQLite の文言はログにだけ残す（2026-11-13、利用者が決めた）

## Constraints

- readonly、busy、revision の不一致など、I/O エラー以外では開き直さない
- 保存に失敗している間は、切り替えと通常の終了を中止する決まりを変えない

## Alternatives Considered

- **共有メモリのファイル（`-shm`）を使う通常のモード**：外付けドライブが外れたあとの保存で、アプリが落ちたので却下した
- **SQLite の文言（「database disk image is malformed」など）を画面に出す**：DB が壊れたと読めてしまうので却下した

## Consequences

- 同じライブラリを2つの Kura で同時に開けない
- Kura が開いている間は、`sqlite3` などでライブラリの DB を見られない
