# ADR-0018: 特徴量はサムネイルから、1スレッドで計算する

## Status

accepted

## Date

2026-11-15

## Context (Why)

特徴量は、取り込み後にバックグラウンドで計算する。計算中も利用者は他の操作を続けられる必要がある（FR-604）。2万枚の計算時間を短くしたい。

## Intent (What)

- 内容と構図は、元の画像ではなくサムネイル（幅320px）から計算する（2026-11-15、利用者と決めた）
- ポーズもサムネイルから計算する（2026-11-18、タスク12で利用者が決めた）
- 推論は1スレッドで始める。スレッド数はワーカー側の設定に置く。増やすかは、計算中のスクロールを測ってから決める（2026-11-15、利用者と決めた）
- ワーカーは ONNX Runtime で動かす。ONNX で動かない、遅すぎるなどのときは、PyTorch に勝手に切り替えず、実測を添えて利用者に相談する

## Alternatives Considered

- **元の画像から計算する**：元の画像は読み込みに1枚約100ms（ポーズでは約125ms）かかる。モデルの入力はサムネイルより小さい。スパイクで比べると、内容の上位10件の重なりは平均88%だった。ポーズでは、サムネイルの方が約5倍速く（2万枚で約11分と約54分）、人物の見逃しも少なかった（212枚で11枚と18枚）
- **全コアで推論する**：スパイクでは、全コアでも1スレッドの約2倍にしかならなかった。計算中の一覧の動きも測っていなかった

## Consequences

- 2万枚の内容の計算は約17分（1スレッド）、ポーズは約11分の見込み
- 元の画像とは並びが少し変わる
