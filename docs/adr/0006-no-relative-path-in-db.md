# ADR-0006: カテゴリとフォルダを1対1にし、DB に画像のパスを持たない

## Status

accepted

## Date

2026-11-04

## Context (Why)

Pinterest に頼らず、資料を手元のフォルダに持ち続けたい。アプリがなくても Finder で画像を開ける必要がある（NFR-05）。1つのフォルダに画像が集まると、Finder での表示が重くなる。カテゴリ名を変えたときに、DB の更新が途中で失敗すると、パスとカテゴリが食い違うおそれがある。

## Intent (What)

- カテゴリはフォルダに1対1で対応する。画像1枚は1つのカテゴリに属する。複数の分類に入れたいときはタグを使う
- DB には画像の相対パスを保存しない。画像のパスは、カテゴリの親子関係とファイル名から組み立てる
- カテゴリ名を変えたときに更新する DB の行は、カテゴリの1行で済む

## Alternatives Considered

- **DB に相対パスを保存する**：カテゴリ名を変えると、配下のカテゴリと画像のすべての行を書き換える必要がある。途中で失敗すると、パスとカテゴリが食い違うので却下した
- **同じ画像を複数のカテゴリに入れる（ファイルを複製する）**：重複の検出（FR-204）と矛盾するので却下した
- **同じ画像を複数のカテゴリに入れる（シンボリックリンクかエイリアス）**：Finder や iCloud での扱いが不安定なので却下した

## Consequences

- 利用者が Finder で見るフォルダの構成と、アプリのカテゴリが一致する
- 1枚の画像を複数のカテゴリに見せることはできない
- ライブラリの外にあるファイルを登録する形（`docs/requirements.md` の10章の .clip の案 B）とは相性が悪い
