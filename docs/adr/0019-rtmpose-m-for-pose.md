# ADR-0019: ポーズの骨格推定に RTMPose-m を使い、反転したポーズを同じとみなす

## Status

accepted

## Date

2026-11-18

## Context (Why)

類似画像検索の「ポーズ」の観点では、腕を上げて振り返る、片膝を立てて座る、のような体の姿勢を比べたい（5.6）。フェーズ3の後半（3b）の進め方は、2026-11-17 に利用者と決めた。

- 3a と同じく、スパイク（`spikes/pose/`）の並びを見て利用者が選ぶ
- 比べるのは RTMPose-s と RTMPose-m（人物の検出は YOLOX-tiny を共通にする）、RTMO-s の3つ
- 複数人の扱いと、左右反転したポーズを同じとみなすかも、同じスパイクで決める

スパイクには、ドキュメント用の見本の写真に、座る・寝る・背面・上半身だけ・複数人などの写真を足した274枚を使った。

## Intent (What)

- 骨格推定は RTMPose-m にする。人物の枠を YOLOX-tiny で出し、枠ごとに関節（COCO 17点）を出す（2026-11-18、タスク12で利用者が決めた）
- 複数人の画像は、関節が足りる全員の骨格を持ち、比べる人物の組のうち一番近い組の類似度を使う。集合写真の中の1人のポーズでも見つかる
- 左右反転したポーズを同じとみなす。作画では参考画像を反転して使えるため
- 画像ごとの結果は「人物なし」「人物はいるが、比べられる関節が足りない」「ポーズあり」の3つに分けて記録する。画面で理由を出せる
- 回転はそろえない。寝ている人と立っている人は似ていないとする
- 画面のスライダーの名前は「体の姿勢」、説明は「手足や胴の向き」にする

## Constraints

- ワーカーの JSONL の出力を壊さない。ワーカーのスレッド数を設定できる
- モデルはライセンスの条件の範囲で取得する（[ADR-0020](0020-download-models-on-demand.md)）

## Alternatives Considered

- **RTMPose-s**：並びの質で外した
- **RTMO-s**：骨格を出せたときの精度は良く見えた。しかし、人物が写っているのに「人物なし」になる画像が多く（人物の写真212枚で27枚。RTMPose-m は4枚）、複数人の検出も甘かった
- **YOLO-Pose**：Ultralytics のコードとモデルは AGPL-3.0 で、MIT の Kura に同梱できないので外した
- **MediaPipe**：今の配布物は TFLite の `.task` で、ONNX Runtime でそのまま動かせないので外した
- **複数人の画像で、一番大きい1人だけを比べる**：集合写真の中の1人のポーズで探せないので、全員を持つ方を選んだ
- **スパイクで使った RTMLib をそのまま使う**：読み込み時に `print()` で標準出力に書く（ワーカーの JSONL を壊す）、セッションの設定（スレッド数）を渡せない、依存に OpenCV（約138MB）が入る、の3点で却下した。前後処理は NumPy と Pillow で書き直した（タスク13）

## Consequences

- 2万枚のポーズの計算は、内容の計算に約11分加わる見込み
- モデルは YOLOX-tiny（20.3MB）と RTMPose-m（54.3MB）で、合わせて約75MB
- 人物の写真212枚で「ポーズあり」にならなかったのは11枚。うち7枚は関節が足りない画像（手だけ、胸元や胴体のアップ）で、人物を見逃したのは4枚
- 計測の結果は `spikes/pose/README.md` にある
