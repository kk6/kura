# ADR-0009: URL からの取り込みを保留し、ダウンロード元の記録を読んで元URLにする

## Status

accepted

## Date

2026-11-06

## Context (Why)

利用者は、ブラウザで見つけた画像を Chrome の拡張機能でダウンロードしてから取り込んでいる。元の画像の URL は残しておきたい（FR-302、FR-208）。アプリで URL を入力して取り込む手順（5.3）は、拡張機能でダウンロードするより手間がかかる。アプリは画像も特徴量も外部へ送らない（NFR-08）。

## Intent (What)

- URL からの取り込み（FR-301〜FR-306）はフェーズ5まで保留する（2026-11-06、利用者と決めた）
- 取り込むファイルにダウンロード元の記録（macOS の `kMDItemWhereFroms`）があれば、1番目を画像URL、2番目を掲載ページURLとして保存する（FR-208）。Chrome でダウンロードしたファイルにこの順で記録されることは、利用者の手元で確かめた
- 元URLの取得・保存・補完と、ブラウザで開く操作はフェーズ2で作る（2026-11-08、利用者と決めた）
  - 1番目と2番目を個別に検査し、有効な HTTP・HTTPS の URL だけを保存する。欠けた URL を推測しない
  - 既存の元URLは上書きしない。補完はライブラリの中のファイルだけを読む
  - 記録の読み取りに失敗しても、画像の取り込みは続ける
  - URL の有効性を調べるための通信はしない
- タスク13〜16で、次の決まりを置いた（2026-11-12、利用者が認めた）
  - 空文字列の項目は欠けた項目として扱い、注意を出さない（Chrome は参照元がないダウンロードで2番目を空文字列にする）
  - 詳細パネルの元URLのリンクを押すと、画面は画像の ID だけを渡す。Rust が DB の値を確かめ直してから、既定のブラウザに渡す
  - リンクは `<a>` 要素にしない。WebKit の右クリックの「リンクを開く」で、アプリのウィンドウ自身が外のページを読み込まないようにするため

## Non-goals

- 元URLの手入力・編集・削除（時期は `docs/requirements.md` の10章の未決事項）
- 起動時の自動の補完

## Constraints

- NFR-08、NFR-09：元URLの取得・保存・補完は通信しない。元URLは、利用者のクリックで既定のブラウザに渡すだけにする

## Alternatives Considered

- **アプリに URL の入力欄を置いて取り込む**（5.3）：拡張機能でダウンロードするより手間がかかるので保留した。作るなら、入力欄より、Kura 向けの Chrome 拡張を作る形を先に検討する
- **Spotlight（`mdls`）の結果だけで記録の有無を判定する**：2026-11-08 にテスト用のファイルで試したとき、`mdls` が値を返さなくても属性を直接読めた。そこで属性を直接読む
- **詳細パネルのリンクを `<a>` 要素にする**：アプリのウィンドウが外のページを読み込むおそれがあるので却下した

## Consequences

- 利用者は今のダウンロードの手順のまま、元URLを残せる
- 2026-11-08 の調べでは、テスト用のファイルに付けた記録が、コピーと上書きしない名前変更で保たれた（macOS 27.0.1 arm64、Rust 1.97.0、APFS）。過去の実画像やすべてのファイルシステムで保たれるかは確かめていない。本物の資料フォルダは調べていない
- 記録のないファイルは、元URLなしで取り込まれる
