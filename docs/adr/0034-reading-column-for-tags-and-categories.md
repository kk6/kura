# ADR-0034: タグとカテゴリの読み仮名を DB の列に持ち、照らすのは画面の wanakana で行う

## Status

accepted

## Date

2026-11-28

## Context (Why)

タグとカテゴリの名前は漢字が多い（「座り」「手」）。候補を出すとき、かな漢字変換を確定する前のローマ字やかなで探せると早い（FR-418）。漢字の名前をローマ字やかなで照らすには、名前の読みが要る。

読みをどこから得るかで、DB の形と、配布物の大きさと、検索の当たり方が変わる。一度 DB に列を足すと、戻すにはマイグレーションが要る。

## Intent (What)

- タグ（tags）とカテゴリ（categories）に読み仮名の列を1つずつ足す。読み仮名はひらがなで持ち、カタカナで入れてもひらがなに直して保存する。空の文字列は「付けていない」を表す
- 照らすのは今の候補の絞り込みと同じく画面（TypeScript）で行う。ローマ字とカタカナの入力は wanakana でひらがなに直し、名前と読み仮名（どちらもひらがなに直したもの）に含むかを見る
- 読み仮名のない名前も、ひらがなかカタカナならローマ字で当たる
- ファイル名とメモは照らし方を変えない

## Non-goals

- 漢字の名前から読みを自動で推定すること
- 1つのタグやカテゴリに複数の読みを持つこと
- ファイル名とメモをローマ字で照らすこと

## Constraints

- 外部への通信を増やさない（NFR-08）
- 2万枚のライブラリで、絞り込みが0.5秒以内（NFR-02）
- DB の列を足すのはマイグレーションの末尾に1つ足して行い、移行の前に `kura.db` の写しを残す（ADR-0027）

## Alternatives Considered

- **rustmigemo の辞書で漢字の名前を読みに展開する**：読みを付ける手間はない。辞書が数 MB あり配布物が大きくなる。辞書の読みは一般語向けで、作画の資料に付けた独自の名前（「あおり」「煽り構図」など）で外れたり、関係のない読みで当たったりする。外れたときに利用者が直す手段がないので却下した
- **読み仮名を持たない（ひらがな・カタカナの名前だけをローマ字で照らす）**：DB を変えずに済む。漢字の名前が多いので、いちばん探したい「座り」が「suwari」で出ず、FR-418 の目的を満たさないので却下した
- **ローマ字の変換を Rust の wana_kana で行う**：照らす処理は画面の候補の絞り込みにある（ADR-0015 と同じく一覧のデータを画面が持つ）。キーを打つたびに Rust を呼ぶと往復が増え、変換だけを別の言語に置くと照らし方が2か所に分かれるので却下した。保存するときのカタカナからひらがなへの直しは、文字コードをずらすだけなので Rust で依存なしに行う

## Consequences

- 漢字の名前は、利用者が読み仮名を付けたものだけがローマ字とかなで当たる
- 読み仮名を変えても DB だけが変わり、ファイルやフォルダは動かない
- 入力の末尾の、かなにならないローマ字（「suwar」の「r」）は除いて照らすので、打ち途中でも候補が出る。その分、打ち途中では読みが前方で一致するほかの名前（「すわる」）も出る
