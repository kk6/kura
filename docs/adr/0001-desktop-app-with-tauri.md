# ADR-0001: ブラウザで開くウェブアプリではなく、デスクトップアプリにする

## Status

accepted

## Date

2026-11-04

## Context (Why)

Kura は、手元の参考画像を取り込み、整理し、作画中に描画ソフトの横で参照するためのアプリである。参照用のウィンドウは描画ソフトより手前に出し続ける必要がある（FR-705）。カテゴリはフォルダに対応し、取り込み・移動・名前変更で実ファイルを動かす（5.4）。利用者は1人で、macOS（Apple シリコン）だけで使う（NFR-10）。

## Intent (What)

- Kura を macOS のデスクトップアプリとして作る。ウィンドウを最前面に固定でき、ライブラリのファイルを直接動かせる
- 画面はウェブ技術で作る。ファイル、DB、サムネイル、ダウンロードなど OS に関わる処理は、画面とは別のネイティブの層が受け持つ
- 機械学習の処理は、さらに別のプロセスが受け持つ（[ADR-0002](0002-ml-worker-onedir-bundle.md)）

## Constraints

- ライブラリに書き込むのはネイティブの層だけにする。機械学習のプロセスは画像を読んで結果を返すだけで、ファイルも DB も変えない
- 外部への通信は NFR-08 の範囲に限る

## Alternatives Considered

- **ブラウザで開くローカルウェブアプリ**：最前面表示（FR-705）と、ローカルのファイル操作が難しいため却下した
- 採用した技術と選んだ理由は次のとおり
  - アプリの基盤（Tauri 2）：ローカルファイルを直接操作でき、最前面表示などのウィンドウ制御もできる
  - 画面（React + TypeScript）：一覧画面とボードをウェブ技術で作れる
  - データ保存（SQLite）：1ファイルで管理でき、ライブラリごと持ち運べる
  - 機械学習（Python、環境は uv で管理）：骨格推定や画像埋め込みのライブラリがそろっている

## Consequences

- 最前面表示、不透明度、ファイル操作を、アプリの中で完結して作れる
- 画面（TypeScript）、ネイティブの層（Rust）、機械学習（Python）の3つの言語を保守する
- Windows には対応しない（NFR-10）
