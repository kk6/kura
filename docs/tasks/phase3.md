# フェーズ3 タスク一覧（類似画像検索）

最終更新：2026-11-14

`docs/requirements.md` の「9. 開発フェーズと優先度」のフェーズ3を、作業の単位に分けた一覧です。上から順に進めます。各タスクは、前のタスクが終わっていることを前提にしています。仕様は要件定義書の5.6、画面の決まりは [design.md](../design.md) を正本とします。

進み具合：すべて未着手。

完了条件：重みを変えると、結果の並びが期待どおりに変わる。利用者が [phase3-check.md](phase3-check.md) をリリース用ビルドで通しで確認する。

## 進め方

フェーズ3は前半（3a）と後半（3b）に分けます（2026-11-14 に利用者と決めた）。

- 3a（タスク0〜11）：ワーカーの同梱、特徴量の計算、内容と構図の類似検索、重みのスライダー。終わったら一度リリースする
- 3b（タスク12〜16）：ポーズの類似検索。未決事項の2件（骨格推定モデルの選定、複数人が写った画像の扱い）は、タスク12で利用者に質問して決める。タスク13〜15の中身は、決まってから書き直す

- Should：FR-603

- フェーズ3に入れないもの：FR-606（骨格の重ね表示。スパイクの中で開発用に出すだけ）、FR-607（文章での検索）、FR-608（ギャラリー外の画像から探す）、FR-609（自動のタグ付け）、類似検索のショートカットとメニューバーの項目。どれもフェーズ4

## 各タスク共通の決まり

- 画面・文言を変えたタスクで、その都度 `docs/user-guide.md` を更新する。色・文字サイズ・余白は `src/styles/tokens.css` の変数だけを使う。画面はモックの開発サーバーを Playwright で開き、スクリーンショットで見た目を確かめる
- ライブラリに書き込むのは Rust だけにする。Python は画像を読んで特徴量を返すだけにする
- 開発側は本物の資料フォルダに触れない。モデルの比較と確認には、見本の写真（読み取り専用）と `scripts/` で作ったダミーを使う。見本の写真そのものと、それを写した結果の画像はコミットしない
- 外への通信は、利用者が設定で ON にしたときのモデルのダウンロードだけにする（NFR-08）。CI とテストではモデルをダウンロードしない
- Rust のコマンド、DB、ワーカーを変えたら、`.claude/skills/verify-kura/` の隔離した実アプリで確かめる。ワーカーの同梱、ダウンロード、バックグラウンドの計算は、モックの e2e の合格で代えない
- スパイク（`spikes/similarity/`）のコードを本体から参照しない
- マージ前に、利用者が実アプリで対象の操作を確かめる
