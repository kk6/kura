## 進め方

フェーズ4は4つに分けます。4a、4a-2、4b は、それぞれ終わったら一度リリースします。

- 4a（タスク0〜10）：作った機能の手直し。小さく早く済むものを先に行う
- 4a-2（タスク30〜37）：0.6.1 を使って見つかった手直し。後から足したので、番号は30から振る。4a の後、4b の前に行う。未決事項（設定のページの種類の分け方）は、タスク30で利用者に質問して決める
- 4b（タスク11〜19）：類似画像検索の拡張。未決事項（重複の整理の細部、ショートカットとメニューバーの項目）は、タスク11で利用者に質問して決める
- 4c（タスク20〜29）：残りの Should と Could。未決事項（隠すモードのボードとプレビューへの適用）と、直接追加（FR-710）を入れるかは、タスク20で利用者に質問して決める

## 各タスク共通の決まり

- 画面・文言を変えたタスクで、その都度 `docs/user-guide.md` を更新する。色・文字サイズ・余白は `src/styles/tokens.css` の変数だけを使う。画面はモックの開発サーバーを Playwright で開き、スクリーンショットで見た目を確かめる
- Tauri のコマンドを足したら、`main.rs`、`src/mocks/ipc.ts`、画面の `invoke` をそろえる
- Rust のコマンド、DB、ファイル操作を変えたら、`.claude/skills/verify-kura/` の隔離した実アプリで確かめる。ボードの保存のキューを変えたら `verify-board-save` を流す
- 開発側は本物の資料フォルダに触れない。試すには見本の写真（読み取り専用）と `scripts/` で作ったダミーを使う
- 外への通信は、利用者が設定で ON にしたときのモデルのダウンロードだけにする（NFR-08）
- マージ前に、利用者が実アプリで対象の操作を確かめる
