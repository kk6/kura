[要件定義書](../requirements.md) の5.2・5.7・6〜10章について、実装前の対話で決めた内容を作業単位に分けた一覧です。仕様は要件定義書、画面の決まりは [design.md](../design.md) を正本とします。

完了条件：作画中にこのアプリだけで参考画像を並べられる。利用者が [phase2-check.md](phase2-check.md) をリリース用ビルドで通しで確認する。

## 各タスク共通の完了条件

- 画面・文言を変えたタスクで、その都度 `docs/user-guide.md` を更新する。タスク20まで先送りしない。画面はモック＋Playwrightで見た目を確認し、必要なら `npm run docs:screenshots` で撮り直す
- 色・サイズ・余白は `src/styles/tokens.css` を使う。追加トークンはdesign.mdと同時に定義する
- Rustのファイル操作は失敗時も含めテストを先に書く。DB・Rustコマンド変更は `.claude/skills/verify-kura/` の隔離実アプリで確認する。別ウィンドウ・メニューバー・最前面・不透明度・ネイティブダイアログはモックe2eの合格で代替しない
- 失敗ケースはダミーのデータと隔離環境で再現する。書き込み失敗は `src-tauri/src/category.rs` のlock/unlock方式を使う。Unix権限の変更だけを根拠にしない
- `fileops.rs`、`library.rs` のconnect/apply_op、`pending_ops` を変えたら `.claude/skills/verify-crash-safe-move/check.sh` を実行する
- まとまりの分け方・開始ブリーフ・メイン側の統合手順は [phase2-sessions.md](phase2-sessions.md)。マージ前に利用者が実アプリで対象操作を確認する
