# Finder での変更を反映する

利用者が Kura の外（Finder）でライブラリの中の画像やフォルダを足したり、移したり、消したりしても、Kura は起動時と「差分を確認」（↻）を押したときに差分を見つけて一覧に反映する。消えた画像は「見つからない」画像になる。

## Sub-features

- `sync-add`：ライブラリのフォルダに足した画像が登録される
- `sync-move`：別のカテゴリのフォルダへ移した画像のカテゴリが変わる（タグとメモは残る）
- `sync-missing`：消した画像が「見つからない」画像になる
- `sync-startup`：起動時にも同じ反映をする

## How to get to it (user POV)

- サイドバーの「カテゴリ」の見出しの ↻（aria-label「差分を確認」）
- アプリの起動

## Driving it with computer-use

Preconditions:

- `$V launch <id>`（見本）。ステータスバーに「Finder での変更はありません」。
- Finder の操作の代わりに、run のライブラリの中のファイルをシェルで動かす。これは利用者が Finder でする変更の再現で、Kura の外からの変更という点で同じ。

- **足す・移す・消す。** シェルで `runs/<id>/lib` の中を変える：`$V src <id> 31` で作った画像のうち見本にない `ref_00030.*` を `lib/src/手/` へ `cp`、`lib/src/服飾/` の1枚を `lib/src/手/` へ `mv`、`lib/src/背景/室内/` の1枚を `rm`（run のライブラリの中だけ）。
- **反映する。** サイドバーの「差分を確認」を押す。ステータスバーに反映の結果が出て、`app.log` に `差分を反映しました：登録 1、移動 1、…、見つからない 1、…`。
- **確かめる。** 「手」の件数が2増え、「服飾」と「室内」が1減る。`$V db <id> "select file_name, category_id, missing_at from images where missing_at is not null"` に消した1枚。見つからない画像の一覧（aria-label「見つからない画像」）に出る。

## Gotchas

- Kura はフォルダを常に見張っていない。↻ を押す前は一覧が変わらないのが正しい動き。
- `.kura/` の中や `_未分類` の名前を直接いじると、Finder の操作の再現ではなくなる。触るのはカテゴリのフォルダの画像だけ。
- `gen_dev_library.py` は番号ごとに同じ中身を作る。`ref_00000`〜`ref_00029` は見本と同じ中身なので、足すと重複として扱われる。足すのは `ref_00030` 以降にする。
- `sync-startup` はまだ手順にしていない。`launch` は使用済みの run id を受け付けないので、止めた run のライブラリを変えて開き直す手順がない。確かめるときは、そのことを「通せなかった入り口」として報告する。
