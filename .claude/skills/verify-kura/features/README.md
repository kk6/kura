# Kura 検証マップ

Kura の利用者から見える動きを実アプリで確かめるための、手順の置き場所。実アプリを動かす前にこの索引を読み、該当する機能のファイルを手順として使う。起動・証跡・後片付けは `../SKILL.md`。

## 前提の状態

- `$V`（`.claude/skills/verify-kura/kura-verify.sh`）で起動した、隔離済みの Kura だけを操作する。`$V doctor <id>` が全部 `ok`。
- 見本のライブラリ（`$V launch <id>` の既定）：画像 30枚。すべて `src` カテゴリの下にあり、未分類は 0枚、ゴミ箱は 0枚。カテゴリは `src` / `_重複`、`ポーズ`（`座り`、`振り返り`、`立ち`）、`手`、`服飾`、`背景`（`室内`、`屋外`、`空のフォルダ`）。タグ、メモ、評価はなし。
- 取り込み元が要る手順は `$V src <id> [枚数]` で `runs/<id>/src/` を作る。30枚のとき、取り込みは 30枚、スキップは 5件（重複と非対応形式）。

## 操作の決まり

- 各手順は、ほかに書いていなければ見本のライブラリから始める。run は手順ごとに新しくする。
- 画面操作とメニュー操作は `../SKILL.md` の Drive から選んだ環境別手順に従う。座標は直前の screenshot から読み、相手は画面の文字で探す。
- フォルダ選択のダイアログは ⌘⇧G → 絶対パス → Return → 「開く」。
- `$V db` は確認だけに使う。状態は画面の操作で作る。

## 証拠と、できなかったことの報告

- 操作の前と後の screenshot、変化した DB の行、実ファイルの位置（`ls`）をそろえる。
- 証拠には、機能のファイル名と、使った入り口（ボタン、キー、メニュー）を書き添える。
- 入り口を通せなかったときは、試した操作と満たせなかった前提を書く。別の入り口で通したものを、通せなかった入り口の検証済みとして報告しない。

## 機能のファイルの形

各ファイルは H1 と、利用者から見た動きの1段落で始まり、次の4つの H2 をこの順に持つ：`Sub-features`、`How to get to it (user POV)`、`Driving it with computer-use`、`Gotchas`。
