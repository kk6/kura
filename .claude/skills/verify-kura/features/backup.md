# 管理情報のバックアップ

利用者は設定の「バックアップ」の「管理情報をエクスポート…」で、ライブラリの管理情報（カテゴリ、タグ、メモなどの `kura.db`）を1つのファイルに書き出せる。画像ファイルと `.kura/features.db` は含まない。書き出しは SQLite のバックアップ機能で、別名（`<名前>.tmp`）に書いてから置き換える。

## Sub-features

- `backup-export`：保存のダイアログで場所と名前（既定は `<ライブラリ名>-<日付>.db`）を選ぶと書き出し、設定に「<パス> にエクスポートしました」と出る。失敗すると「管理情報をエクスポートできません（…）」。`app.log` に `DB を書き出しました：<パス>`
- `backup-import`：開くダイアログ（「インポートする管理情報を選ぶ」）で選んだファイルで、今の管理情報を置き換える。確認「管理情報をインポート」に書き出した日時と2つの画像枚数が出る。置き換える前の写しを `.kura/backups/kura-before-restore-<日時>.db` に残し、開き直して差分の確認をする。`app.log` に `管理情報を戻しました：<パス>`（FR-107）

## How to get to it (user POV)

- 設定（ヘッダーの歯車、⌘,）→「バックアップ」→「管理情報をエクスポート…」→ 保存のダイアログ → 「保存」
- 設定 →「バックアップ」→「管理情報をインポート…」→ 開くダイアログ →「開く」→ 確認の「インポート」

## Driving it with computer-use

Preconditions:

- `$V launch <id>`（見本）。

- **書き出す。** 設定の「管理情報をエクスポート…」を押す。保存のダイアログが出て、名前の欄が `lib-<日付>.db`。保存先を run の中にして「保存」。設定に「… にエクスポートしました」。`sqlite3 <書き出したファイル> "select count(*) from images"` が見本の 30。
- 今は画面からは通せない（2026-11-19、run `mvk-a`）。保存のダイアログは利用者の「ダウンロード」を開き、computer-use は保存のダイアログの中で ⌘⇧G を使えず、「.」で始まるフォルダ（`.claude/`）も選べない。利用者の実際のフォルダには書かないので、ここで「キャンセル」した。書き出しの中身は `library.rs` の `backup` のテストで確かめる。画面から通すには、利用者に保存先を選んでもらう

## Gotchas

- 開くダイアログ（取り込み、ライブラリを作る・開く）では ⌘⇧G で run のパスへ移れるが、保存のダイアログでは移れない。drivers/claude.md
- ダイアログを開いたまま放置しない。キャンセルしてから設定を閉じる

## 管理情報をインポートする（FR-107）

エクスポートを画面から通せないときは、見本の `kura.db` の写し（`cp .claude/tmp/verify-kura/template/.kura/kura.db runs/<id>/backup-in/old.db`。見本の WAL が空なら写しだけで足りる）を「見本の時点でエクスポートしたもの」として選ぶ。開くダイアログは ⌘⇧G で run の中へ移れる。2026-11-25 の `mvs-25a`：タグ1件を付けた後にインポートし、確認に「（30枚）で、今の管理情報（29枚）を置き換えます」、`tags` が0件、`backups/` に `kura-before-restore-<日時>.db`、`pending_ops` が0。

1. 隔離した見本のライブラリで、1枚にタグを付ける。アイデアボードをオンにし、空のボードを作ってから管理情報を run 内にエクスポートする。書き出した DB はそのまま残す。
2. その画像のタグを付け替え、カテゴリを移す。手順1のボードを開いて画像を置く。画面と画像のパスを控える。
3. 設定の「管理情報をインポート…」で書き出した DB を選ぶ。日時と2つの画像枚数が出た確認を撮る。「インポート」を押す。
4. ボードが保存されて閉じ、ライブラリが開き直ることを確かめる。タグは書き出した時点に戻る。カテゴリを移した画像は差分の確認後に今の場所に表示される。ボードを開き直し、書き出した時点の内容が出ることを確かめる。
5. `lib/.kura/backups/` の `kura-before-restore-<日時>.db` を確認する。このファイルをインポートし、手順2で付け替えたタグとボードの内容を確かめる。

- **計算中。** [類似画像検索](similarity.md) の手順でモデルを置き、計算済みの画像がある状態でダミー画像を追加する。特徴量の計算中にインポートを確定する。前後の画面とログを残し、計算済みの画像が再計算されず、未計算分の処理が続くことを確かめる。確定前に計算が終わった場合は、ダミー画像を増やしてやり直す。
- **別のライブラリ。** 重なる画像が半分に満たない別の試し用ライブラリの DB を選ぶ。警告を撮り、キャンセル後も今のタグとボードが残ることを確かめる。
- **管理情報以外。** ダミー画像を選び、エラーが出て今の管理情報が残ることを確かめる。
- **取り込み中。** ダミー画像の取り込み中にインポートを試す。操作が断られ、管理情報が置き換わらないことを確かめる。
- **証跡。** 確認の画面、インポート後の一覧とボード、写しのファイル名を残す。タグと配置は `$V db` で確認し、差分の確認と特徴量の計算は `app.log` を残す。
