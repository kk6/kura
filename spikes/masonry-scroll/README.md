# スパイク2：2万枚のメイソンリー表示を仮想スクロールする

使い捨てのプロトタイプです。本体のコードには使いません。

## 確かめたかったこと

- ダミー画像2万枚のサムネイルを、仮想スクロールのメイソンリー表示で、引っかからずにスクロールできるか（NFR-01）
- 計測は、本体と同じ Tauri の WebView（macOS では WKWebView）で行う

## 試した方法

- `gen_thumbs.py`：幅320pxのダミーのサムネイル（JPEG、縦長・正方形・横長が混ざる）を2万枚と、各画像の幅と高さを書いた `manifest.json` を `.data/` に生成する。ノイズを入れて、1枚あたり平均32KB（合計634MB）にした
- `src/masonry.ts`：配置の計算
  - 画像を並び順のとおりに、一番短い列へ順に置く（FR-501）。幅と高さは manifest から読むので、画像を読み込む前に全体の配置が決まる
  - 表示範囲の画像は、列ごとの二分探索で探す
- `src/App.tsx`：表示範囲と、その上下1画面分の画像だけを `<img>` として描く。位置は `transform` で指定する。スクロールの反映は1フレームに1回にする。画像は Tauri のアセットプロトコル（`convertFileSrc`）でローカルのファイルから読む
- `src/bench.ts`：自動でスクロールして測る
  - 一定の速さでのスクロール：毎秒1500pxを6秒と、毎秒6000pxを6秒。フレームの間隔と、画面内で描けていない画像の割合を測る
  - 遠くへの移動（スクロールバーを掴んで飛ぶ操作の代わり）：ランダムな位置へ20回飛び、2フレーム後と0.5秒後に、描けていない画像の割合を測る
- `SPIKE_BENCH=1` を付けて起動すると計測し、結果の JSON を標準出力に出して終了する。`SPIKE_COL` で列の幅の目安を変える

## 結果

環境：macOS 27.0.1（Appleシリコン）、ウィンドウ 1440×900、リリースビルド

| 項目 | 列の幅 200px（7列） | 列の幅 120px（12列） |
| --- | --- | --- |
| 同時に描く `<img>` の数 | 54 | 129 |
| 毎秒1500px：フレーム間隔の p50 / p99 / 最大 | 17 / 18 / 18ms | 17 / 18 / 24ms |
| 毎秒6000px：フレーム間隔の p50 / p99 / 最大 | 17 / 18 / 18ms | 17 / 18 / 18ms |
| 33ms を超えたフレーム（1フレーム以上の落ち） | 0 | 0 |
| 一定の速さでのスクロール中の空白の割合 | 0% | 0% |
| 遠くへ飛んだ2フレーム後の空白の割合 | 0% | 6.7% |
| 遠くへ飛んだ0.5秒後の空白の割合 | 0% | 0% |

- どちらの列の幅でも、60fps を保ってスクロールできた。NFR-01 は満たせる見込み
- 2万枚の配置の計算は、画面の幅が変わったときだけ行う。計算時間は計測していないが、体感できる遅れはなかった

### 確かめていないこと

- ディスクのキャッシュが冷えた状態。サムネイルを生成した直後に測ったので、ファイルは OS のキャッシュに載っていた。外付けの HDD や再起動直後は、遠くへ飛んだ直後の空白が増える可能性がある
- トラックパッドでの実際のスクロール。計測は `scrollTop` をプログラムで動かしたもので、メインスレッドの負荷としては実際より厳しい条件になる
- 120Hz の画面での動き（WKWebView のフレームは60Hzだった）
- 並べ替え・絞り込みで配置を計算し直す時間と、メモリ使用量

## 本体で採用する方針

- 一覧は、ライブラリなどを使わず、このスパイクと同じ方法で自前で作る
  - DB に保存した幅と高さから、全体の配置を先に計算する
  - 列ごとの二分探索で表示範囲を求め、表示範囲と上下1画面分だけを描く
  - 位置は `transform` で指定し、スクロールの反映は1フレームに1回にする
- サムネイルは `.kura/` の下のファイルを、Tauri のアセットプロトコルで直接読む。DB を通したり、Base64 にして渡したりしない
- アセットプロトコルの読み込み範囲（scope）は、開いたライブラリの `.kura/` の下だけに絞る。パスは正規化してから渡す（`..` を含むパスは scope の判定に通らなかった）

## 動かし方

```bash
npm install
uv run gen_thumbs.py        # .data/ に2万枚を生成（約5秒、634MB）
npm run icon
npx tauri build
SPIKE_BENCH=1 SPIKE_COL=120 src-tauri/target/release/kura-spike-masonry
```
