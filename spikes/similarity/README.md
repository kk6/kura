# スパイク：類似画像検索のモデルと特徴量（フェーズ3のタスク0）

使い捨てのプロトタイプです。本体のコードには使いません。

状態：終わった（2026-11-15）。利用者が選んだ結果は「決めたこと」と、要件定義書の4章・5.6・10章にある。

## 確かめたかったこと

1. 内容の埋め込みモデルの比較（CLIP 系、多言語の SigLIP 系、DINOv2 系）。ONNX Runtime で動くか
2. サムネイル（幅320px）から計算した結果と、元の画像から計算した結果の差
3. 構図の特徴量（縮めたグレースケール画像、格子ごとのエッジの向きの分布）が目で見て足りるか
4. 観点ごとの類似度の幅のそろえ方
5. 2万件のベクトルの全件比較にかかる時間
6. 各モデルのライセンス、モデルとワーカーの大きさ、1枚あたりの計算時間

## 試した方法

- 見本の写真88枚（人物29、動物28、小物7、風景24）を読み取り専用で使った。本物の資料は使っていない
- `features.py`：サムネイルを本体と同じ条件（幅320px、JPEG 品質85）で `out/thumbs/` に作る。4つのモデルを Hugging Face から `models/` にダウンロードし、ONNX Runtime（CPU）で、サムネイルと元の画像の両方から埋め込みを計算する。構図の特徴量も計算する。1枚ずつ計算し、読み込み・前処理と推論の時間を分けて測る
- `report.py`：類似度の統計を `out/stats.md` に、並びを見比べるページを `out/index.html` に出す
- `bench.py`：乱数の2万件を SQLite に入れ、読み出しと全件比較の時間を測る
- `worker_stub.py`：ONNX Runtime、NumPy、Pillow を読み込むだけのスクリプト。PyInstaller の onedir にして大きさを測る

候補のモデル（どれも画像側だけの ONNX、float32）：

| 名前 | 取得元 | 入力 | 次元 |
| --- | --- | --- | --- |
| clip-b32 | `Xenova/clip-vit-base-patch32` の `onnx/vision_model.onnx` | 短辺224に縮めて中央を切り出す | 512 |
| siglip2-b16 | `onnx-community/siglip2-base-patch16-224-ONNX` の `onnx/vision_model.onnx` | 縦横比を無視して224×224に縮める | 768 |
| dinov2-s | `onnx-community/dinov2-small` の `onnx/model.onnx` | 短辺256に縮めて中央の224を切り出す | 384 |
| dinov2-b | `onnx-community/dinov2-base` の `onnx/model.onnx` | 同上 | 768 |

構図の特徴量（学習済みモデルを使わない。縦横比を無視して正方形に縮める）：

- gray：16×16 のグレースケール。平均を引いて長さ1にそろえる（256次元）
- edge：128×128 のグレースケールを 4×4 の格子に分け、格子ごとにエッジの向き8方向の分布を、エッジの強さで重み付けして数える（128次元）
- gray+edge：2つの類似度の平均

類似度はどれもコサイン類似度。

## 結果

環境：macOS（Apple M5 Max）、Python 3.14.4、onnxruntime 1.32.0、numpy 2.5.4、Pillow 13.0.0。計測は1回だけで、計測中のロードアベレージは4〜5だった（ほかの処理が動いていた）。時間は目安として読む。

### 1. 内容のモデル

4つとも ONNX Runtime で動いた。

| モデル | ライセンス | 画像側のモデル | 文章側のモデル（フェーズ4で要る） | 文章の言語 |
| --- | --- | --- | --- | --- |
| clip-b32 | MIT（Xenova のカードの表記。openai のカードには license 欄がない） | 352MB | 254MB | 英語だけ |
| siglip2-b16 | Apache-2.0（`google/siglip2-base-patch16-224` のカード） | 372MB | 1130MB（fp16 は 565MB、int8 は 283MB。どちらも試していない） | 多言語 |
| dinov2-s | Apache-2.0（`facebook/dinov2-small` のカード） | 89MB | なし（画像だけ） | - |
| dinov2-b | Apache-2.0（`facebook/dinov2-base` のカード） | 347MB | なし（画像だけ） | - |

- MIT と Apache-2.0 は再配布を認めている。Apache-2.0 は、ライセンスの写しと著作権表示を添える必要がある（タスク10）
- ONNX に変換したリポジトリ（Xenova、onnx-community）のカードには、license 欄がないものがある。元のモデルのライセンスに従うものとして扱った
- 候補から外したもの：`jinaai/jina-clip-v2`（多言語の CLIP 系だが CC BY-NC 4.0）、DINOv3（独自のライセンス）

サムネイル1枚あたりの時間（中央値。最初の3枚を除く85枚）：

| モデル | 読み込みと前処理 | 推論（全コア） | 推論（1スレッド） | 2万枚の見込み（全コア / 1スレッド） |
| --- | --- | --- | --- | --- |
| clip-b32 | 1.7ms | 9.4ms（7.7〜20.1） | 12.4ms | 約4分 / 約5分 |
| siglip2-b16 | 1.2ms | 24.0ms（22.4〜26.2） | 48.5ms | 約8分 / 約17分 |
| dinov2-s | 1.7ms | 20.5ms（16.9〜27.8） | 31.7ms | 約7分 / 約11分 |
| dinov2-b | 1.7ms | 45.4ms（40.1〜67.5） | 81.4ms | 約16分 / 約28分 |

- 2万枚の見込みは、1枚の時間に2万を掛けた値。実際に2万枚を流してはいない
- 全コアでも1スレッドの2倍ほどしか速くならない。何が上限になっているかは調べていない
- セッションの読み込みは 50〜230ms。構図の特徴量は1枚 0.2ms 未満で、内容の計算に比べて無視できる
- CoreML での実行、fp16 や量子化したモデルは試していない

並びの比較（`out/index.html` の1番目の節）：

- 同じカテゴリの画像が上位10件に占める割合は、clip-b32 92%、siglip2-b16 93%、dinov2-s 90%、dinov2-b 90%。カテゴリが4つしかない粗い目安で、この差に意味があるとは言えない
- 上位10件の重なりは、clip-b32 と siglip2-b16 で 69%、DINOv2 の2つで 73%、CLIP 系と DINOv2 系で 61〜63%
- 開発側が数枚の基準画像で見た印象：clip-b32 と siglip2-b16 は、写っているものの種類でまとまる（富士山と五重塔の夜景を基準にすると、日本の風景が並ぶ）。DINOv2 は、7件目あたりから色や明るさの似た別の被写体（猫、人物）が混ざる。**これは数枚を見ただけの印象で、最終の判断は利用者が行う**

### 2. サムネイルと元の画像の差

| 観点 | 同じ画像の2つのベクトルの類似度（最小 / 中央） | 上位10件の重なり（平均） |
| --- | --- | --- |
| clip-b32 | 0.896 / 0.959 | 83% |
| siglip2-b16 | 0.870 / 0.924 | 88% |
| dinov2-s | 0.908 / 0.978 | 91% |
| dinov2-b | 0.855 / 0.975 | 90% |
| gray | 1.000 / 1.000 | 100% |
| edge | 0.995 / 0.999 | 97% |

- 上位10件のうち、サムネイルと元の画像で入れ替わるのは平均1〜2件。入れ替わった画像が見た目に劣るかどうかは確かめていない
- 元の画像は、読み込みと前処理に1枚 93〜110ms かかる（サムネイルは 1.2〜1.7ms）。2万枚で30分以上の差になる

### 3. 構図の特徴量

- 同じカテゴリが上位10件に占める割合は 36〜39%。内容（90%以上）と違い、被写体の種類に引きずられていない
- 開発側が見た印象：gray は明暗の配置に強く反応する（暗い背景の人物を基準にすると、暗い画像が並ぶ）。edge は線の向きと位置に反応する。「構図が似ている」と感じられるかは、利用者が `out/index.html` の2番目の節で判断する

### 4. 類似度の幅

サムネイルから計算した、全組の類似度の分布：

| 観点 | 5% | 50% | 95% |
| --- | --- | --- | --- |
| clip-b32 | 0.40 | 0.55 | 0.78 |
| siglip2-b16 | 0.40 | 0.53 | 0.75 |
| dinov2-s | -0.06 | 0.03 | 0.34 |
| dinov2-b | -0.04 | 0.02 | 0.28 |
| gray | -0.43 | 0.04 | 0.52 |
| edge | 0.35 | 0.58 | 0.76 |
| gray+edge | 0.06 | 0.30 | 0.56 |

- 幅が観点ごとに違う（siglip2-b16 は 0.35、gray は 0.95）。そのまま重みを掛けて足すと、同じ重みでも gray が約3倍強く働く
- `out/index.html` の3番目の節で、4つのそろえ方（そろえない、最小〜最大を 0〜1 に、平均0・標準偏差1に、順位に置き換える）を切り替えて並びを見られる

### 5. 2万件の全件比較

2万枚 × 2観点（768次元と384次元、float32）の乱数。7回の中央値：

| 処理 | 時間 |
| --- | --- |
| SQLite から全部読む | 36.2ms（32.9〜45.7） |
| 全件比較と並べ替え | 1.5ms（1.4〜2.1） |

- NFR-03 の2秒に対して十分に小さい。時間の大半は SQLite からの読み出し
- Python と NumPy での値。本体は Rust なので、タスク6で測り直す
- `features.db` は 127MB になった（ライブラリごとに `.kura/` に置く大きさ）

### 6. ワーカーの大きさ

- ONNX Runtime、NumPy、Pillow を入れた PyInstaller の onedir は 112MB（Pillow だけだった `spikes/tauri-python/` は 27MB）
- `PATH=/usr/bin:/bin` だけの環境で起動し、3つのライブラリを読み込めた

## 開発側のおすすめ（選ぶ前に出したもの）

- **内容のモデル：siglip2-b16。** 画像どうしの並びは clip-b32 と同程度に見え、日本語の文章を扱えるのはこれだけ（5.6 の選び方）。引き換えに、計算は clip-b32 の約2.2倍かかり、フェーズ4で文章側のモデル（283〜1130MB）が要る
- **計算に使う画像：サムネイル**（5.6 の方針のまま）
- **構図：gray+edge で始める。** 足りるかどうかは利用者の判断
- **幅のそろえ方：基準画像に対する全画像の類似度を、観点ごとに平均0・標準偏差1にそろえてから重みを掛ける。** 絞り込みで並びが変わらないよう、絞り込む前の全画像で計算する。順位に置き換える方法は、飛び抜けて似ている画像との差が消えるので次点

## 決めたこと

2026-11-15 に、利用者が `out/index.html` の並びを見て決めた。

- 内容のモデルは siglip2-b16（`google/siglip2-base-patch16-224`）にする
- 内容と構図は、サムネイル（幅320px）から計算する
- 構図は gray+edge で 3a を進める。被写体の位置を使う方法に見直すかは、3b の開始時に決める
- 類似度の幅は、基準画像に対する全画像の類似度を、観点ごとに平均0・標準偏差1にそろえてから重みを掛ける

## 動かし方

```bash
cd spikes/similarity
uv run features.py /Users/kk6/Projects/kura-library   # モデル約1.2GBを models/ にダウンロードする
uv run report.py
uv run bench.py
uv run --with pyinstaller pyinstaller --onedir --noconfirm worker_stub.py && du -sh dist/worker_stub
```

`out/index.html` は、画像を相対パスで読むので HTTP で開く。Claude Code からは `.claude/launch.json` の `similarity-spike`（http://localhost:5199）で開ける。手元では次のとおり。

```bash
python3 -m http.server 5199 --bind 127.0.0.1 --directory out
```

`models/`、`out/`、`dist/` はコミットしない（`.gitignore`）。
