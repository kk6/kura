# スパイク3：移動の途中で止まっても画像を失わない

使い捨てのプロトタイプです。本体のコードには使いません。

## 確かめたかったこと

- ファイルの移動と DB の更新の途中で処理が止まったとき、画像を失わず、DB とファイルの不整合を検出できるか（NFR-06）
- 止まった後に、元の整った状態へ戻せるか

## 試した方法

画像1枚を、カテゴリ「座り」から「立ち」へ移す処理を、次の3段階で行う（`src/main.rs` の `move_image`）。

1. 移動の予定（移動元と移動先）を DB の `pending_ops` テーブルに記録してコミットする
2. 上書きしない名前変更（macOS の `renamex_np` に `RENAME_EXCL` を付ける）でファイルを移す。移動先に同名ファイルがあれば失敗する
3. 1つのトランザクションで、`images` を移動先に更新し、予定を消してコミットする

起動時に呼ぶ `recover` は、残っている予定ごとに、実ファイルがどちらにあるかを見て処理する。

| 実ファイルの位置 | 意味 | recover の動き |
| --- | --- | --- |
| 移動元だけ | 2の前に止まった | 予定を消す（移動を取り消す） |
| 移動先だけ | 2の後に止まった | DB を移動先に合わせ、予定を消す（移動を完了させる） |
| 両方、またはどちらにもない | 想定外 | 何もせず予定を残す。`check` が報告し、利用者に知らせる |

`check` は不整合を列挙する（残っている予定、ファイルがない画像、DB にないファイル）。

テスト（`tests/crash.rs`）は、環境変数 `KURA_CRASH_AT` で決めた位置で `abort` してプロセスを止め、次のことを確かめる。移動先には、最初から同名のファイル `立ち/a.jpg` を置いてある。

- 画像の中身を持つファイルが、ライブラリの中にちょうど1つある
- 移動先の同名ファイルが上書きされていない
- `check` が不整合を検出する
- `recover` の後に `check` が不整合なしを返す

## 結果

| 止めた位置 | 止まった直後の check | recover 後の状態 | 結果 |
| --- | --- | --- | --- |
| 止めない | 不整合なし | `立ち/a (2).jpg` に移動済み | 合格 |
| 1の後（`after_journal`） | 予定が残っていると検出 | 移動元のまま | 合格 |
| 2の後（`after_rename`） | 予定の残り、ファイルがない画像（移動元）、DB にないファイル（移動先）を検出 | `立ち/a (2).jpg` に移動済み | 合格 |
| 3のコミット前（`before_commit`） | 2の後と同じ | `立ち/a (2).jpg` に移動済み | 合格 |

- どの位置で止めても、画像は失われず、上書きもされなかった
- 予定の記録があるので、止まった位置を推測せずに、実ファイルの位置だけで戻し方を決められた

### 確かめていないこと

- exFAT・HFS+ のドライブでの `RENAME_EXCL`。ディスクイメージを作る `hdiutil` の実行が許可されなかったため、内蔵ディスク（APFS）でしか確かめていない。exFAT で使えない場合は、「移動先がないことを確かめてから rename」に切り替える必要がある（その間に Finder でファイルが置かれると上書きの恐れがある）
- 電源断。プロセスを止めるテストだけを行った。DB は `synchronous=FULL` にしたが、macOS の `fsync` はディスクのキャッシュまでは書き出さない（`F_FULLFSYNC` が必要）
- 別のボリュームへの移動（コピー＋削除になる）。取り込み（コピー）では、移動先に一時的な名前で書き出してから rename する手順が必要
- カテゴリのフォルダの移動・名前変更。同じ手順（予定の記録 → rename → DB 更新）でできる見込み

## 本体で採用する方針

- ファイルを動かす操作（移動、名前変更、カテゴリのフォルダの移動・名前変更、ゴミ箱への移動と復元）は、すべて「予定を DB に記録 → 上書きしない rename → DB の更新と予定の削除を1トランザクション」の3段階で行う
- 起動時に、残っている予定を実ファイルの位置に合わせて完了させるか取り消す。どちらとも決められない場合は予定を残し、利用者に知らせる
- 上書きしない rename には `renamex_np` の `RENAME_EXCL` を使う。exFAT で使えるかは、フェーズ1のタスク2で確かめる
- DB は WAL モードと `synchronous=FULL` で使う
- 7章のテーブルに `pending_ops`（移動の予定）を加える
